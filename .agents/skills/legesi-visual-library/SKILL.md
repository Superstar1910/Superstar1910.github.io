# Legesi Visual Library

Use this skill for ChatGPT visual-library archival. Read [repository contract](references/repository-contract.md) and [audit template](references/audit-template.md). Operate on `Superstar1910/Superstar1910.github.io`; never create an alternative catalogue or gallery.

1. **Scope and discovery.** Distinguish one chat from a whole Project. Examine all accessible in-scope conversations, uploads, generated images, revisions, documents and related repositories. Search by meaning as well as filenames. Report inaccessible conversations and missing files; never claim complete access without evidence.
2. **Recovery.** Retrieve verified original final files. Reconcile previous catalogue and inventory entries using source references, hashes and visual comparison where possible. An unavailable original is `pending-original-recovery`; do not fabricate it or publish a screenshot as the original.
3. **Final approval.** Select one explicitly approved or demonstrably publication-authorised version per distinct deliverable. Exclude superseded, rejected, duplicated and ambiguous outputs. Later generation alone is not approval. Recreation requires separate explicit permission and approval.
4. **Context and safeguards.** Record conversation/Project, thesis, sector, geography, audience, visual type, related article/project, source period, rights and revision evidence. Check confidential clients/transactions, personal privacy/consent, attribution, licences, quantitative accuracy and illustrative labelling. Do not put restricted images or sensitive metadata in public GitHub.
5. **Chat preview.** Display the actual recovered approved visuals in the current conversation when supported; group by theme with title, context, approval and proposed file path. If rendering is unavailable, provide verified references and disclose the limitation.
6. **Archive and test.** Follow existing catalogue schema and paths. Optimise derivatives without changing content, remove sensitive EXIF, create thumbnails, check IDs/files/rights and run `python scripts/validate_visual_library.py` plus site quality and visual/navigation checks. Fix failures; never bypass gates.
7. **Controlled publication.** Use feature branch, verified-only commit, asset-by-asset PR, CI checks, authorised merge and live deployment verification at https://legesi.xyz/visuals/. PR creation/merge alone is not publication proof. Report blockers without blocking other eligible assets.
8. **Report.** Re-display live images when possible and report distinct counts for discovered, recovered, approved, displayed, archived, merged and published; excluded/restricted/pending assets; sources reviewed; CI/PR/deployment evidence and verified links.

Preserve existing assets and URLs. Work incrementally, avoiding re-imports. Execute permitted steps now without promising background execution.
