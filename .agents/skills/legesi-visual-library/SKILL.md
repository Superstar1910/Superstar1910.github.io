# Legesi Visual Library v2.0

Operate on the existing Legesi.xyz architecture, not a parallel gallery. Read [repository contract](references/repository-contract.md). For each task, consult the relevant procedures: [discovery](references/discovery.md), [provenance](references/provenance.md), [publication](references/publication.md), [takedown](references/takedown.md), and [audit](references/audit-template.md).

1. **Scope and coverage.** Identify whether the request covers a single chat or an entire Project. Inventory *accessible* chats, files, Library sources, generated visuals, embedded figures and related GitHub assets. Deduplicate across sources. Record the exact sources examined and inaccessible areas; never claim complete historical access without evidence.
2. **Recover and preserve.** Recover original bytes when authorised; retain source hash, dimensions, provenance, revision group and an immutable source identifier. Preserve every authorised original in an appropriate private archive before discarding workspace copies. Do not fabricate lost originals or treat a screenshot/contact sheet as the source.
3. **Decide independently.** Preserve ≠ approve ≠ publish. Select final versions based on documented user approval; distinguish alternatives, duplicates and revisions. Separate explicit rights/consent, confidentiality, private financial data and fact/date checks. Never infer public clearance from recovery alone.
4. **Preview.** Display renderable recovered finals in ChatGPT with context and status. State when an original cannot be displayed. Identify historical values as historical.
5. **Public intake.** Prepare optimised final derivatives and thumbnails, strip sensitive metadata, use the canonical catalogue and only the existing importer. Validate ZIP paths, integrity, unique IDs/hashes, allowed MIME, rights/approval records, privacy and matching assets. Do not publish restricted originals or private ledger entries.
6. **Release.** Use a feature/intake branch, PR, required CI, authorised merge, deployment and actual live URL/image verification. An uploaded ZIP, merged PR or valid catalogue alone does not prove live publication. Do not bypass failed checks.
7. **Withdrawals.** On request, remove both gallery record and public bytes, retain only in a verified **private** repository outside deployable paths; check website, caches and historical exposure caveats. See [takedown](references/takedown.md).
8. **Report and resume.** Use the [audit template](references/audit-template.md), giving separate counts for candidates, originals, approved finals, public assets, private alternatives, inaccessible and live verified. Update the ledger incrementally, with evidence and no double counting.

Execute permitted actions now with minimal user intervention; request authorisation only for genuinely unresolved privacy, rights or recreation questions. Never promise unexecuted background work.
