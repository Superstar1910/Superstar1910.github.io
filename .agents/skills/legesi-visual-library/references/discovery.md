# Discovery and coverage procedure

## Enumerate sources
- Identify chat versus Project scope; search all accessible conversations/attachments, personal Library records, Project files, generated visual outputs and embedded document images. Search by project names, research topics, graphical keywords and image formats, not filenames alone.
- Inspect current canonical catalogue and historical inventories first. Compare public repo images and private archives to avoid rediscovering completed work.
- Record **source identifier, type, location/scope, number of records examined, retrieval attempt and result** in a coverage register. A personal Library search is not equivalent to an exhaustive historical-chat search.
- Mark each source `searched`, `partially accessible`, `unavailable` or `not searched`. Separate discoverable metadata from authorised original-byte access.
- Categorise images as candidate public research, related alternative, unpublished/confidential, reference-only screenshot, third-party, project source document or unrelated; do not bulk publish entire Library folders.

## Incremental identity
- Stable visual family ID survives renames; each actual file gets SHA-256, dimensions and source reference. Identify exact binary duplicates by hash; visual near-duplicates require deliberate comparison.
- Maintain an append/update evidence ledger accessible to the workflow, but **never put private filenames or sensitive source details into a public repo**. A public candidate inventory may contain only non-sensitive summaries.
- Do not mark a Project exhausted merely because all current Library pages were enumerated. Require conversation/source-level coverage and explicit unresolved-access disclosures.
