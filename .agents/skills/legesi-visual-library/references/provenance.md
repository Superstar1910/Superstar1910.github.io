# Preservation, provenance and version governance

## Recover
Prefer exact original file bytes from accessible original conversation, authorised Project/Library files, private archive, then verified source repository. Never re-create missing historical originals silently or replace originals with screenshots/contact sheets.

For every visual record: stable family ID; source-file SHA-256; filename; dimensions; originating conversation/Project; research thesis and editorial context; asset type; source dates; related article/tool URL; rights; confidentiality; approval evidence; revision parent; selected final status; public/private destination; validation and live verification evidence.

## Dispositions
- `discovered`: metadata only
- `recovered`: verified original bytes obtained
- `preserved-private`: original copied and verified in private archive
- `approved-final`: explicit selection for a distinct deliverable
- `publication-cleared`: rights, privacy, factual/date review recorded
- `intake`, `merged`, `live-verified`: separately evidenced publishing stages
- `superseded`, `duplicate`, `restricted`, `pending-recovery`, `withdrawn`: not public gallery candidates

Never equate 'different SHA' with 'different final deliverable'. Keep alternatives as a revision family; retain all authorised originals privately, but publish only final-approved representations. Historical values in charts do not become current claims.
